 MÉTODO OBTER USUARIO - PARA ATUALIZAR:
	- Recebe a matrícula do usuário.
	- Procura esse usuário no banco de dados usando o usuarioRepository.
	- Se o usuário não existir, lança uma exceção informando que ele não foi encontrado.
	- Se existir, converte a UsuarioEntity em um UsuarioAtualizarDto através do mapper.
	- Retorna o DTO para preencher os campos do formulário de edição.

 MÉTODO ATUALIZAR USUARIO:
	- Recebe um DTO contendo os dados atualizados do usuário.
	- Procura no banco o usuário correspondente à matrícula informada no DTO.
	- Se o usuário não existir, lança uma exceção.
	- Se existir, atualiza os atributos da entidade (nome, data de nascimento, e-mail e senha) com os novos valores do DTO.
	- Salva a entidade atualizada no banco de dados usando save().
	- Retorna true indicando que a atualização foi realizada com sucesso.

RESERVAS:
	[ ] id
	[ ] colaborador - Identificação do colaborador que realizou a reserva.
  	[ ] recurso - Identificação do espaço ou equipamento que foi solicitado.
	[ ] data - campo que indica a data de reserva do espaço ou equipamento.
	[ ] hora inicial - campo que indica a hora de reserva do espaço ou equipamento.
	[ ] hora final - campo que indica a hora de reserva do espaço ou equipamento.
	[ ] cancelamento - campo que indica a data de cancelamento da reserva. (preenchido apenas através da função de cancelar reserva que ficará disponível apenas na tela de atualização de reserva)
	
	OBSERVAÇÃO: campo descritivo do cancelamento do espaço ou equipamento (que será solicitado ao acessar a função de cancelamento).

 REGRAS:
	1 – O campo “colaborador” deve ser obrigatório.
	2 – O campo “equipamento” ou “espaço” deve ser obrigatório.
	3 – O campo “data” deve ser obrigatório.
	4 – O campo “cancelamento” deve armazenar a data de cancelamento e não deve ser preenchido ao realizar um registro de uma reserva nova.
	5 – O sistema deve criticar um registro de reserva para um código de colaborador sem cadastro.
	6 – O sistema deve criticar o registro de uma reserva para um código de espaço ou recurso sem cadastro.
	7 – Na tela de cancelamento o sistema deverá exibir os dados da reserva como ‘somente leitura’ e exibir um botão de ‘confirmar cancelamento’. Quando esta ação foi realizada, o sistema irá apenas atualizar o registro de reserva com a data atual no campo “data de cancelamento” finalizando a reserva e que só pode acontecer 1 dia antes da data agendada.
	8 - Para cada registro novo, a data de cancelamento deverá ser preenchida como nula ou em branco.
	9 – O sistema deverá bloquear a atualização de uma reserva já registrada, apenas o cancelamento será possível.
	10 - O sistema deverá na tela de cancelamento solicitar ao usuário uma descrição do motivo do cancelamento e deve ser informado obrigatoriamente.
